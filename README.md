# Учебный RAG: LangChain + Groq

Три Python-файла и простой сайт. Реализовано задание со слайда 11: RAG с веб-интерфейсом на LangChain по выданным статьям Хабра. Исходный облегчённый набор из 10 000 статей включён целиком.

## Запуск в PyCharm

Откройте папку `rag_simple`. Интерпретатор проекта: `.venv\Scripts\python.exe` (Python 3.14.8).

После клонирования репозитория один раз создайте окружение и установите зависимости в терминале PyCharm:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Вставьте свой ключ Groq в `.env`. В **Settings → Project → Python Interpreter** выберите существующий интерпретатор `.venv\Scripts\python.exe`. Если окружение и `.env` уже настроены, повторять эти шаги не нужно.

Нажмите правой кнопкой на `app.py` → **Run 'app'**. Файл сам запустит Streamlit. Также можно выбрать готовую конфигурацию **«Сайт RAG»** и нажать **Shift+F10**. Сайт откроется по адресу `http://127.0.0.1:8501`. Остановка — красная кнопка Stop или **Ctrl+F2**. Перед повторным запуском остановите предыдущий сервер.

Ключ Groq должен быть записан в `.env`, как описано ниже.

## Запуск в VS Code

Проект настроен на **Python 3.14.8**. Откройте именно папку `rag_simple` через **File → Open Folder**, затем **Terminal → New Terminal**. После обновления Python перезапустите VS Code. Интерпретатор проекта: `.venv\Scripts\python.exe`.

Один раз создайте окружение и установите библиотеки:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Один раз настройте ключ в бэкенде: откройте файл `.env` рядом с `app.py` и заполните строку `GROQ_API_KEY=ваш_ключ_Groq`. Если файла нет, скопируйте `.env.example` в `.env`. Ключ берётся из [личного кабинета Groq](https://console.groq.com/keys). На сайте поля для ключа нет. `.env` исключён из Git и из архива проекта.

При каждом запуске выполните:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте адрес из терминала, обычно `http://localhost:8501`. Введите вопрос и нажмите «Получить ответ». Остановка сервера: `Ctrl+C` в терминале. При первом вопросе весь набор читается и индексируется; следующие вопросы используют готовый поиск в памяти. После перезапуска поиск строится заново.

Если окружение уже выбрано в VS Code и активировано, достаточно `python -m streamlit run app.py`.

## Что изучать

| Файл | За что отвечает |
|---|---|
| `loader.py` | Читает CSV, очищает HTML, создаёт `Document` |
| `rag.py` | Делит текст, ищет фрагменты, вызывает модель через LangChain |
| `app.py` | Поле вопроса, кнопка и вывод ответа с источниками |

Последовательность: **статьи → фрагменты → поиск → контекст и вопрос → Groq → ответ**.

Модель — [Qwen 3.8 27B](https://console.groq.com/docs/model/qwen/qwen3.8-27b), идентификатор `qwen/qwen3.8-27b`. Параметры: `temperature=0.6`, `max_completion_tokens=2048`, `top_p=0.95`, `reasoning_effort="default"`. Цепочка отдаёт ответ частями через `chain.stream()`, а сайт показывает их через `st.write_stream()`. На экран выводится итоговый ответ без внутренних рассуждений.

Из лекции используются `Document`, `RecursiveCharacterTextSplitter`, retriever, `ChatPromptTemplate`, чат-модель и `StrOutputParser`. Главная строка LCEL в `rag.py`: `chain = prompt | model | StrOutputParser()`.

Поиск здесь — готовый `TFIDFRetriever` из LangChain. TF-IDF представляет фрагменты числовыми векторами и сравнивает слова вопроса со словами статей. Это простой статистический поиск, а не нейросетевые эмбеддинги; он хуже понимает перефразирование. Отдельные FAISS, BM25, база данных, сервер API и JavaScript для этого решения не нужны. Groq используется только для генерации ответа по найденным текстам.

`ChatGroq` представлен среди интеграций на слайде 4. По ТЗ конкретная LLM и вид веб-интерфейса не заданы. Название модели хранится в константе `MODEL` в `rag.py`; если она недоступна вашему аккаунту, укажите доступную модель из [списка Groq](https://console.groq.com/docs/models). Используется [официальная интеграция ChatGroq для LangChain](https://docs.langchain.com/oss/python/integrations/chat/groq).

## Проверка перед защитой

1. Задайте вопрос «Что изменилось в политике SoundCloud относительно искусственного интеллекта?».
2. Дождитесь ответа и откройте найденные источники. Сопоставьте утверждения модели с текстом статей.
3. Задайте свой вопрос или вопрос преподавателя.
4. Введите `qzxvzzstttvvh`: приложение должно сообщить, что подходящие фрагменты не найдены.

Система не обучает LLM: она находит нужные фрагменты и добавляет их в промпт. Источники могут быть похожими, но не содержать достаточного ответа; промпт требует сообщать о недостатке сведений. Даже с контекстом модель может ошибиться.

Ключ читается бэкендом из `.env` или переменной окружения `GROQ_API_KEY` и не выводится в интерфейсе. Для полного ответа нужен действующий Groq API-ключ и доступ к выбранной модели. Без ключа можно читать код и проверить локальный поиск отдельно, но генерация не выполняется.

Проверено при подготовке: чтение всех 10 000 статей и построение 141 096 фрагментов (около 70 секунд на этом компьютере), поиск источников для вопросов о SoundCloud, uv и Docker, отказ для неизвестного слова, форма сайта без поля ключа. Передача вопроса и контекста через LCEL проверена с тестовой моделью. Короткий реальный потоковый запрос к Qwen через Groq также прошёл успешно. Для запуска на другом компьютере потребуется собственный действующий ключ.

## Что хранится в Git

В репозитории находятся код, зависимости, инструкция, `.env.example`, общие настройки запуска IDE и исходный сжатый набор статей. `.gitignore` исключает ключи из `.env`, виртуальные окружения, кэш, личные настройки `.idea`, логи и архивы. Файл `.env.example` содержит только шаблон без ключа.
